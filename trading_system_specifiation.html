Modular Strategy Trading System

Technical Specification — Unified Brain, Multi-Strategy Testing (Jev + Quantitative), Historical Replay & Paper/Live Execution

1. System Overview

The Modular Strategy Trading System is a high-performance, developer-friendly trading platform built in Python 3.11+. It streams real-time market data from Coinbase, aggregates market structure, evaluates customizable trading strategies, enforces strict risk limits, and executes orders via a high-fidelity paper trading simulator or live Coinbase APIs.

The system is architected for dual-mode operation:

  • Live / Paper Streaming Mode: Ingests live ticks and candles via Coinbase WebSocket, continually running decision cycles in real-time.
  • Historical Replay / Backtesting Mode: Starts at any arbitrary point in time (e.g. --start-time "2 days ago"), fetching missing historical candles on demand, replaying them through the engine, and testing multiple strategies side-by-side on identical historical data.

2. v2.0 Architecture Updates & Key Decisions

Three Key Architectural Changes in v2.0:
  1. Unified Strategy Brain: The previously separate State Builder, Decision Engine, and Risk Manager modules are condensed into a single, cohesive StrategyBrain component for the initial phase. This removes IPC latency, simplifies testing, eliminates circular data synchronization, and makes historical replay trivial. (The component maintains clean internal functional boundaries so it can be split into distributed microservices when scaling later).
  2. Pluggable Multi-Strategy Framework: The platform is decoupled from any single decision model. Jev (TypeSafe AI) is implemented as a first-class strategy plug-in alongside technical and quantitative baselines (e.g., EMA Trend, MACD Divergence, RSI Mean-Reversion). Any number of strategies can be defined, loaded, and compared.
  3. Arbitrary Historical Replay & Comparison: The engine can be initialized with any start_time in the past. It fetches and caches required candle history, simulates execution without lookahead bias, tracks independent virtual portfolios per strategy, and outputs side-by-side comparative performance metrics.

6. Module: Coinbase Connector & Data Feeds

File: src/coinbase_connector.py
Libraries: coinbase-advanced-py, httpx, asyncio
Modes: Live Streaming & Historical Backfill

Responsibilities

  • Maintain resilient WebSocket connection to Coinbase Advanced Trade (wss://advanced-trade-ws.coinbase.com).
  • Subscribe to ticker and candles channels for designated trading pairs (e.g., BTC-USD).
  • Aggregate raw ticks into 1-minute OHLCV candles; flush completed candles to SQLite.
  • Historical Data Provider: Provide fetch_historical_candles(pair, start_time, end_time) with automatic pagination (300 candles per REST request) to satisfy any replay start time requested by the user.
  • Automatic Gap-filling: On startup or reconnect, detect missing candles between last DB timestamp and current time, backfilling via REST before resuming feed.

Historical Fetching & Gap-Fill Logic

async def ensure_candles_available(pair: str, start_ts: float, end_ts: float, db: Database):
    # Check existing coverage in SQLite
    missing_ranges = db.find_missing_candle_ranges(pair, start_ts, end_ts, granularity=60)
    
    for range_start, range_end in missing_ranges:
        logger.info(f"Backfilling {pair} from {range_start} to {range_end} via Coinbase REST")
        curr = range_start
        while curr < range_end:
            batch_end = min(curr + (300 * 60), range_end)
            candles = await rest_client.get_candles(pair, start=curr, end=batch_end, granularity="ONE_MINUTE")
            db.insert_candles(candles, source="rest_backfill")
            curr = batch_end
            await asyncio.sleep(0.1) # Rate-limit safety

7. Module: Strategy Brain (Unified Component)

File: src/brain.py
Subsumes: State Builder + Strategy Evaluator + Risk Manager
Design Rationale: In v1.0, state building, decision making, and risk management were separated into 3 disparate components. In v2.0, they are condensed into one unified Brain component for clean local execution, effortless unit testing, and ultra-fast historical replay. When the system scales to distributed production, the internal pipeline methods can be exposed as microservices with zero architectural friction.

Internal Brain Pipeline

Component Interface

class StrategyBrain:
    def __init__(self, strategy: BaseStrategy, risk_config: RiskConfig, feature_config: FeatureConfig):
        self.strategy = strategy
        self.risk_config = risk_config
        self.feature_config = feature_config

    async def evaluate(
        self,
        pair: str,
        timestamp: datetime,
        candles_df: pd.DataFrame,
        portfolio: PortfolioSnapshot
    ) -> EvaluationResult:
        # 1. Feature computation
        state: MarketState = self.build_market_state(pair, timestamp, candles_df)
        
        # 2. Strategy evaluation
        raw_signal: StrategySignal = await self.strategy.generate_signal(state, portfolio)
        
        # 3. Deterministic risk rules
        risk_result: RiskDecision = self.apply_risk_rules(raw_signal, portfolio, timestamp)
        
        return EvaluationResult(
            timestamp=timestamp,
            state=state,
            signal=raw_signal,
            risk=risk_result,
            order_intent=self.compute_order_intent(raw_signal, risk_result, portfolio)
        )

9. Module: Historical Replay & Comparison Engine

File: src/replay_engine.py
Capabilities: Start at any historical time (e.g. 2 days ago, 1 month ago); replay multiple strategies across the exact same candle stream; zero forward lookahead bias.

Replay Workflow

1

Parse Replay Target & Validate Data

User specifies --start-time "2026-09-25T00:00:00Z" (or relative --start-time 2d) and strategies to test (e.g. --strategies jev,ema_macd,rsi_bb). The Replay Engine verifies SQLite has all 1m candles for [start_time - lookback_buffer, end_time]. If not, it requests the gap from Coinbase REST.

2

Initialize Isolated Virtual Portfolios

A separate PaperPortfolio instance with identical starting cash (e.g. $10,000) is initialized for each strategy being evaluated under a unique run_id.

3

Step-by-Step Simulation (No Lookahead Bias)

The engine advances through timestamps at the configured interval (e.g., 60 seconds). At each step T:

  • A strict historical slice [T - 200 candles : T] is passed to the StrategyBrain. Under no circumstances can indicators see candles at > T.
  • For each strategy, the Brain evaluates the state and risk rules.
  • If an order is approved, the PaperTradingEngine fills the trade at candle close / ticker price at timestamp T with simulated taker fee (0.6%) and spread slippage (0.05%).
  • Portfolio values and trade metrics are recorded with the strategy's run_id.
4

Generate Comparative Benchmark Leaderboard

Outputs a rich Markdown/terminal table comparing Win Rate, Cumulative Return, Max Drawdown, Sharpe Ratio, Profit Factor, and Total Fees across all tested strategies.

# Running a comparative replay from CLI
$ python main.py replay \
    --pair BTC-USD \
    --start-time "2d" \
    --strategies "jev,ema_macd_trend,rsi_bb_reversion" \
    --initial-cash 10000

10. Module: Multi-Portfolio Paper Simulator

File: src/paper_engine.py
Responsibility: Manages isolated virtual balance sheets for any active strategy run.

Key Capabilities

  • Multi-tenant Portfolio Support: Maintains separate virtual cash, coin balances, average entry prices, and high-water marks keyed by (strategy_id, run_id).
  • Realistic Cost Modeling: Applies configurable taker fee (default 0.60%) and realistic bid-ask slippage (default 0.05%).
  • Order Rejection Guardrails: Rejects BUY orders if virtual cash is insufficient; rejects SELL orders if coin quantity is 0.
  • Persistence: Immediately persists all simulated trades and portfolio snapshots to SQLite so tests can be paused, analyzed, or resumed.

11. Module: Order Executor (Live Mode)

File: src/order_executor.py
Library: coinbase-advanced-py (RESTClient)
Safety Status: Hard deterministic safeguards enforced by Python code (independent of strategy models).

Safeguards

  • Max Order Size Cap: Strict absolute dollar ceiling per trade (e.g. $100 micro-live limit).
  • Daily Loss Limit Circuit Breaker: If realized + unrealized daily loss exceeds 3%, all trading is halted for the calendar day.
  • Pending Order Lock: Will not place a new order if an existing order for the coin pair is in PENDING status.
  • No Automatic Retries: Any API order error causes an immediate log and skip to prevent double-spending loops.

19. CLI & Running Modes

The system features an intuitive CLI to switch between live paper execution and historical replay.

1. Replay Multiple Strategies on Past Data (Arbitrary Start Time)

# Replay the last 2 days across Jev and EMA-MACD trend strategies
python main.py replay --start-time "2d" --strategies "jev,ema_macd" --pair BTC-USD

# Replay from an exact UTC ISO timestamp
python main.py replay --start-time "2026-09-25T00:00:00Z" --strategies "all" --initial-cash 25000

2. Run Paper Trading Live Stream

# Stream live WebSocket feed and trade with virtual paper portfolio
python main.py stream --mode paper --strategy jev --pair BTC-USD

# Warm up on the past 6 hours, then smoothly continue into live stream
python main.py stream --mode paper --strategy jev --catchup-from "6h"

3. Run Micro-Live Trading (Real Capital)

# Live execution with hard safety stops (max $100 per trade)
python main.py stream --mode live --strategy jev --pair BTC-USD --max-order-usd 100

4. Compare Historical Runs

# Print terminal comparison matrix across specific historical run IDs
python main.py compare --runs "run-20260925-jev,run-20260925-ema"

22. Testing & Rollout Roadmap

Phase 1 — Core Unit & Determinism Tests

  • Brain Pipeline: Feed fixed candle fixtures into StrategyBrain. Assert exact indicator mathematical outputs, deterministic risk gating, and mock strategy dispatching.
  • Replay Engine: Verify that historical replay starting at $T_0$ outputs strictly reproducible trade sequences and doesn't access candles at $t > T$.
  • Multi-Portfolio Isolation: Verify that two concurrent strategies maintain distinct virtual balances and trade histories without cross-contamination.

Phase 2 — Multi-Strategy Historical Replay (2–7 Days of Past Data)

  • Run historical replay on the past 48–72 hours across jev_strategy, ema_macd_trend, and rsi_bb_reversion.
  • Evaluate conviction-to-outcome correlation for Jev: check if higher conviction scores correlate with higher trade P&L.
  • Inspect risk threshold sensitivity: tune min_conviction and daily_loss_cap_pct against historical drawdowns.

Phase 3 — Forward Paper Trading (3–5 Days Continuous)

  • Deploy bot in Paper Streaming mode on local laptop.
  • Confirm live WebSocket stability, automated reconnect on sleep/wake, and clean SQLite persistence.

Phase 4 — Micro-Live Trading ($50–100 Real Capital)

  • Switch mode to live with fixed $10 order size.
  • Verify real order routing, fill price precision, real Coinbase fee deductions, and daily loss circuit breaker enforcement.
